排序优先级（核心规则）

只有置顶不会变；其余每小时按投注量自动重排。热度来自游戏的有效注单（默认值 + 每小时新增投注），全平台一份；场馆按热门游戏数量排。想按站点固定位置用置顶；想所有站点一起往前推，把有效注单默认值或场馆排序数值写大；站点不想要的游戏在本站点关闭。

背景

总控「站点场馆管理」下只有「场馆配置总控」「游戏配置总控」两个平台级页面，不分站点：可维护 / 启用 / 停用场馆和游戏、手工改场馆热门游戏数量、批量修改有效注单，但不能按站点调整顺序。场馆置顶、热门置顶、场馆内置顶只在商户后台操作，总控要替站点调整只能登录商户后台或提工单。

另外：总控停用的游戏、场馆仍下发到站点，会出现在站点排序列表里，已置顶的没有处理规则；同一款游戏的原厂版与 MY 版在前台同时出现、位置不同。

本期做三件事：站点选择（现网两页选站点后显示该站点数据）；置顶移到总控（场馆置顶、热门置顶、场馆内置顶都能在总控按站点操作，与商户后台同一份数据）；原厂 / MY 切换由总控控制。同时处理总控停用过滤。商户后台不改。

需求说明

需求点位置说明
1. 站点选择本期新增场馆配置总控、游戏配置总控搜索区新增「站点」（必选）。进入页面不加载数据，选站点并查询后显示该站点的场馆 / 游戏，「序号」改为显示该站点的前台位置（场馆）/ 热门排名（游戏），并追加该站点的列（站点状态、置顶、对应版本、前台显示等）。现网的列与平台级操作（维护 / 启用 / 停用、批量修改有效注单）保留，仍对全平台生效；游戏「排序」删除。场馆「编辑排序数值」删除，热门游戏数量改为显示该站点的值、只读
2. 置顶移到总控本期修改场馆配置总控、场馆游戏排序弹窗、热门游戏排序（新增菜单）商户后台的三类置顶都能在总控按站点操作：场馆置顶（场馆配置总控）、场馆内置顶（场馆配置总控 → 场馆游戏排序）、热门置顶（新增菜单「热门游戏排序」）。规则与商户后台一致：位置从 1 连续、新置顶放末尾、改位置为插入、取消后前移、批量置顶 / 取消、位置快速筛选；与该站点商户后台同一份数据，任一端修改另一端可见
3. 原厂 / MY 切换由总控控制本期新增场馆配置总控、游戏配置总控按站点选择游戏对在前台显示原厂版还是 MY 版，默认 MY：场馆配置总控「原厂 / MY 切换」按场馆对一键切换，「对应 MY 场馆」点击「N 款对应游戏」可查看该场馆对的游戏对并逐个切换；游戏配置总控新增对应版本（显示对方游戏）、前台显示列与筛选，单个「改为原厂 / 改为 MY」与批量切换。前台同一游戏对只显示一款；目标版本已被总控停用时不能切换
4. 总控停用过滤本期修改场馆配置总控、游戏配置总控的「停用」停用的场馆 / 游戏，各站点前台与热门游戏排序、场馆游戏排序列表都不再显示；已置顶的自动取消，其后前移；停用当下生效
5. 维护 / 启用 / 停用可选范围本期修改场馆配置总控、游戏配置总控点维护 / 启用 / 停用后，在确认框里选「只改本站点」或「全部站点」，不默认、必须选。只改本站点改该站点的站点状态（与商户后台同一份），全部站点改总控状态。底部批量操作同样处理
不在本期—场馆顺序仍为 场馆置顶 → 热门游戏数量；商户后台本期不改

维护 / 启用 / 停用（影响范围）

项目规则
入口场馆配置总控、游戏配置总控操作列「维护」「启用」「停用」；两页底部「批量操作」下拉的批量维护、批量启用、批量停用
按钮显示看总控状态与本站点状态：两者都已是维护不显示「维护」；总控启用且本站点开启不显示「启用」；总控停用且本站点关闭不显示「停用」
确认框本期修改标题：单个「停用场馆「X」」，批量「批量停用：已勾选 N 个场馆」；单个时写「当前：总控状态 X　本站点 Y」；「请选择影响范围」两个大块单选，不默认；备注必填，最多 30 字
只改「站点」改该站点的站点状态：维护 → 维护，停用 → 关闭，启用 → 开启；与商户后台厂商管理、游戏管理同一份数据，其他站点不变。游戏关闭后本站点置顶取消；场馆关闭后场馆置顶保留，前台不显示，开启后回到原位。启用时如总控不是启用，写「总控不是启用的，前台仍按总控状态处理」
全部站点改总控状态，对所有站点生效，规则沿用现网与停用过滤；选中后「确定」变红
已是该状态对应选项置灰并写明（如「本站点已是关闭」「总控已是停用」）；批量时写「处理 X 个，另 Y 个已是…，跳过」
校验与提示未选范围提示「请选择影响范围」；未填备注提示「请填写备注」。成功：「已在「站点」设为关闭」「已在「站点」把 N 个游戏设为维护」；全部站点「已停用，所有站点不再显示」「已把 N 个场馆停用，所有站点不再显示」
留痕与批量两种范围都更新最后操作人、时间（总控账号），备注随本次操作保存；批量规则同列表批量操作，总控停用的场馆不可勾选，需单个启用

基本概念

概念说明
总控状态 / 站点状态总控状态：总控设置的维护 / 启用 / 停用，对全平台生效。站点状态：商户设置的开启 / 维护 / 关闭，只影响该站点
场馆置顶前台场馆 Tab、首页场馆区块先后、侧边菜单、场馆页左侧的顺序。每个站点一个队列：场馆置顶 → 热门游戏数量
热门置顶首页热门区、侧边菜单热门、搜索页「热门」、场馆页「热门」的顺序。每个站点一个全站队列：热门置顶 → 热门值
场馆内置顶首页场馆区块内游戏、场馆页「全部」的顺序。每个站点每个场馆一个队列：场馆内置顶 → 热门值
置顶规则位置从 1 连续编号，新置顶放末尾，改位置为插入，取消后其后前移，不限数量；三类置顶总控与商户都能操作，同一份数据
热门值来自游戏配置总控的有效注单，全平台一份，沿用现有逻辑
场馆对 / 游戏对本期场馆对只有 PG电子 ↔ MyPG电子、TaDa 电子 ↔ MyTaDa电子；游戏对为两个厂商都有的游戏（按三方游戏 ID 对应），开发预置，不可修改。只有一方有的游戏为「无对应版本」；其他场馆没有场馆对，相关列显示「-」
前台显示版本本期新增每个站点每款对应游戏一份，前台只显示原厂版或 MY 版；默认显示 MY；只在总控切换

开发测试重点说明

  1. 站点必选：进入不加载数据，选站点查询后显示该站点数据；维护 / 启用 / 停用按确认框所选范围生效，只改本站点时检查其他站点未被改动。
  2. 按站点的数据：所有接口带站点参数，取已查询站点；验证时检查其他站点未被改动。
  3. 三类置顶与商户后台同一份数据：位置任何时候 1 到 N 连续；新增 = N+1；取消 = 其后 −1；修改 = 插入。
  4. 三类队列互相独立：筛选不影响位置计算。
  5. 游戏对置顶按版本：前台只取当前版本，隐藏版本不占位；切换不改置顶；目标版本停用不能切。
  6. 总控停用过滤：下发数据统一过滤，前台与两类排序列表不显示，置顶取消，当下生效；维护沿用现网。
  7. 前台缓存：沿用现网，本需求不提刷新要求。
  8. 平台排序：场馆「编辑排序数值」、游戏「排序」沿用现网，平台级；改的是平台热门值，下个整点各站点按新值重排，要长期靠前需把数值写大。
  9. 后续：商户后台是否做切换下期再定。
